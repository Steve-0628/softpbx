# 01. スコープと要件

## 1. 製品の輪郭

拠点内（オフィス）の内線交換機（PBX）ソフトウェア。**IP 端末とアナログ端末（電話機・FAX 機・
モデム）を扱い、宅外の拠点 PBX とも通話できること**が v1 の必須要件である。

アナログ回線の終端は自社ハードではなく**外付けゲートウェイ（Yamaha NVR500/510 級）**に
委ねる構成が有力。したがって本ソフトウェアはアナログの物理層を持たず、
ゲートウェイを SIP/RTP 側から制御・運用する。

**公衆回線（外線）への接続は想定しない。** 外との通信は拠点間 SIP トランクのみ。

## 2. 機能要件

### 2.1 通話（必須）

- 内線間通話（SIP 端末、アナログ端末の双方）
- **拠点間通話**：宅外の PBX（MikoPBX 互換）と SIP トランク経由で通話（§2.4）
- 保留・保留解除、保留中音楽
- 転送（ブラインド / アテンド）、複数内線への同時着信
- 会議（音声のみ、十数人規模）
- ダイヤルプラン（番号変換・発信制限・番号帯ルーティング）
- アナログ端末への着信音・応答トーンなどの日本仕様
- 発信者番号通知（アナログ端末への FSK: V.23 通知を含む）

### 2.2 ファックス（必須）

- **T.38 ファックス中継**（IP 間、およびアナログ FAX ↔ IP 間のゲートウェイ）
- **G.711 パススルー伝送**（T.38 非対応の相手向けフォールバック）
- **アナログ FAX 機の接続**（ゲートウェイ FXS 経由で内線として登録）
- **ファックスサーバ**：受信 FAX を TIFF → PDF 化してメール送信、送信は PDF/TIFF から発信

### 2.3 アナログ端末・モデム伝送（必須）

- アナログ端末は**外付けゲートウェイ（Yamaha NVR500/510 級）**で接続
  - 電話機・FAX 機・モデム・インターホン等
  - 機器側の FXS ポートから見た着発信・フックスイッチ・着信信号の制御
- **モデム・3.1kHz オーディオ伝送**：アナログモデム信号を壊さずに IP 中継する
  （G.711 + 厳格な遅延管理。V.152 手順はオプション）

### 2.4 拠点間接続（必須）

宅外の拠点 PBX（MikoPBX 互換）と通話する。MikoPBX 同士の接続は **SIP トランク**であり
（SIP で呼制御、RTP で音声）、本ソフトウェアも同じ方式で相互接続する。

- SIP トランク（ピア）機能：相手 PBX の登録/受諾、ダイジェスト認証、IP 認証
- **番号帯ルーティング**：拠点ごとに内線番号帯を割り当て、相手拠点の番号帯へ発信ルート
- 暗号化：SIP over TLS（5061）/ SRTP
- NAT 越え：rport / 対称 RTP / STUN（宅外から受信するケース）
- 相互接続の既知の差異（`fromuser` 無効、Asterisk 系ピアのセッションタイマ挙動など）は
  互換性クイーク層で吸収（docs/05）

### 2.5 管理系（必須・軽量）

- Web UI と API（機能はすべて API から利用可能。UI はクライアントの一つ）
- 設定管理：宣言的 Desired State、変更履歴・ロールバック、検証（dry-run）
- 電話機およびゲートウェイの自動設定（プロビジョニング）
- 軽量保守：設定のエクスポート/インポート、ログ、簡易メトリクス、ソフトウェア更新

## 3. スコープ外（v1 では作らない）

| 領域 | 理由 |
| --- | --- |
| **通話録音・モニタリング** | 明示的に不要 |
| **課金・料金計算・請求** | 明示的に不要 |
| **公衆回線（外線/PSTN）接続** | 想定していない |
| **重い保守機能**（A/B アトミック更新、フルバックアップ/リストア、遠隔診断パッケージ、HA） | 明示的に不要。設定の保存/復元と更新のみ |
| 留守番電話（メッセージ録音） | 録音機能を伴うためスコープ外。必要なら「音声応答のみ」に限定 |
| IVR / ACD / コールセンター | 要件確定待ち（§5） |
| CRM / 外部システム連携 | 要件確定待ち（§5） |
| ISDN デジタル回線 | 不要 |
| WebRTC（ブラウザ通話） | v1 の必須要件ではない |
| マルチテナント / SaaS 化 | 単一組織利用を前提 |

※ 障害解析のために最小限の発着信ログは残すが、**課金用の詳細記録は作らない**。

## 4. 非機能要件

| 領域 | 要件 |
| --- | --- |
| リアルタイム性 | 音声 1 パケット（10/20ms）の処理予算 < 1ms。ジッタバッファは音声で適応、VBD（ファックス/モデム）では固定 |
| 信頼性 | 制御面（管理・設定）が停止しても確立済み通話の音声は切断されない |
| 信頼性（伝送） | ファックス/モデムの信号を劣化させない。欠損・再送・遅延の扱いを VBD で最適化 |
| 容量 | 内線 100、同時通話 50、FAX 同時 4 を目安 |
| 安全性 | TLS / SRTP、ダイジェスト認証、不正アクセス検知（レート制限）、監査ログ |
| 運用性 | 構造化ログ、簡易メトリクス、設定の再現とロールバック |
| 移植性 | Linux x86_64 / aarch64。アナログは外付けゲートウェイ（SIP/RTP 経由） |

## 5. 要件確定待ち（着手前に決める）

1. **IVR / 留守番 / ACD が本当に不要か** — 外線がない前提でも、拠点間着信の自動応答
   （アナウンス）が必要になる場合がある。
2. **アナログゲートウェイの機種確定** — Yamaha NVR500/510 級が有力だが未確定。以下の点を
   機種確定時に検証する（docs/03 §6 の検証項目）。
   - T.38 中継の対応可否と UDPTL 冗長化の挙動
   - G.711 パススルー時のパケット周期・ジッタバッファ挙動（モデム伝送に耐えるか）
   - DTMF の通知方式（RFC 4733 / 帯域内 / SIP INFO）
   - 発信者番号通知（FSK）の伝送方法
   - 設定配信方式（HTTP / TFTP / 独自 API）
3. **電話機メーカーの対応範囲**（自動設定の対象）
4. **FAX の保存期間・容量**
5. **拠点間接続の経路** — 専用線/VPN（Yamaha ルータの IPsec 等）を使うのか、インターネット
   上に直接 SIP TLS で出すのか。前者なら NAT 問題は緩和される。

## 6. リスクと要確認事項

### ★ アナログ端末の品質はゲートウェイ次第

アナログ信号はゲートウェイ内で RTP へ変換されるため、**本ソフトウェア側で遅延やジッタを
直接制御できない**。特にモデム・FAX 伝送はゲートウェイのジッタバッファやコーデック処理で
信号が壊れやすい。

- 通話・G.711 FAX は多くのゲートウェイで成立するが、**モデム伝送は機種依存**。
- 対策：ゲートウェイ特性プロファイル（クイーク層）を用意し、パケット周期・ジッタバッファ・
  VAD の設定を VBD 用に最適化する。ゲートウェイ側の設定も含めて調整する。
- 最悪ケースでモデム伝送だけ縮小する判断もあり得る。**早期に実機検証する**（docs/06）。

### その他のリスク

- **エコー除去（G.168）と VBD の相性**：FAX/モデム検出時にエコー除去・VAD・DTX・
  ジッタバッファ適応・AGC をすべて停止しなければ信号が壊れる（docs/03 §4）。
- **T.38 と実機 FAX の相互運用**：機種・V.34 対応・ECM の組合せが多い。
- **SIP のフィールド汚染**：実在する端末・ゲートウェイ・相手 PBX は標準を守らない。
  互換性クイーク層を最初から分けて作る。
- **拠点間接続の MTU/パケットロス**：インターネット経路では SIP の UDP 分割・ロスが起きる。
  TCP/TLS トランスポートと SRTP を最初から用意する。
