# 07. マイルストーン

価値が出る順に並べる。各マイルストーンには**出口条件**を置き、満たすまで次へ進まない。
録音・課金・外線接続・重い保守は作らないため、標準的な PBX 開発より短縮できる。

| M | 目標 | 目安 | 出口条件 |
| --- | --- | --- | --- |
| **M0** | 骨格が動く | 2〜3 ヶ月 | §1 |
| **M1** | 電話として使える | 3〜4 ヶ月 | §2 |
| **M2** | FAX とアナログ端末 | 4〜6 ヶ月 | §3 |
| **M3** | ファックスサーバとモデム | 3〜4 ヶ月 | §4 |
| **M4** | 製品としての完成 | 3〜4 ヶ月 | §5 |

合計目安 **15〜21 ヶ月**（2〜5 名）。M1 終了で社内トライアル、M2 終了で実顧客の試験導入。

## M0: 骨格が動く

「自作エンジンで電話がつながる」ことの証明と、テスト基盤の確立が目的。

- SIP REGISTER・INVITE/ACK/BYE による内線通話（G.711、RTP 双方向）
- B2BUA の通話 FSM（docs/02 §4）と、シグナリング/メディアのスレッド分離
- ファイルベースストア（Desired State + 通話ログ）と最小 API
- `engine-sim` の DST 基盤（仮想時計・仮想ネットワーク・疑似 SIP 端末）

**出口条件**: docs/08 の受け入れテストがすべて通り、シード固定の DST が CI で回る。

## M1: 電話として使える

- ダイヤルプラン（番号変換・発信制限・番号帯ルーティング）
- 保留/復帰、ブラインド/アテンド転送、会議（音声）
- DTMF（RFC 4733 / 帯域内 / SIP INFO）
- **拠点間 SIP トランク（MikoPBX 互換）**：番号帯ルーティング、TLS/SRTP、NAT 越え
- 早期メディア、セッションタイマ、再 INVITE などの SIP 基本動作
- 互換性クイーク層（docs/05 §3）の仕組み

**出口条件**: MikoPBX 実機と相互接続して拠点間通話・転送が成立。SIP シナリオの
ゴールデンテストが回帰防止として機能する。

## M2: FAX とアナログ端末

- アナログゲートウェイ（NVR500/510 級）の接続：プロビジョニング、特性プロファイル
- アナログ電話機の着発信、発信者番号通知
- **T.38 中継**（IP 間、アナログ FAX ↔ IP）
- **G.711 パススルー**（VBD モード遷移を含む）
- VBD 検出（CNG/CED/V.21 プリアンブル/V.8）

**出口条件**: 実機 FAX（複数メーカー）との送受信が T.38 / パススルー両方で成立。
疑似 FAX 機の DST シナリオが全速度・ECM 有無で通る。

## M3: ファックスサーバとモデム

- ファックスサーバ：受信 → TIFF → PDF → メール、送信 → PDF/TIFF → T.30
- 送受信スプール、再送、結果通知
- **モデム・3.1kHz データ伝送**の成立と安定化（ゲートウェイ依存部分の実機検証）

**出口条件**: FAX 送受信の自動テストが通り、モデム伝送が実機で成立するか
（あるいは成立範囲を文書化するか）が確定する。

## M4: 製品としての完成

- Web UI / API の完成（設定、照会、運用、FAX 送受信、ゲートウェイ管理）
- 電話機・ゲートウェイの自動設定対応機種の確定
- 軽量保守：設定エクスポート/インポート、更新、ログ、簡易メトリクス
- セキュリティ（TLS/SRTP、認証、レート制限、監査ログ）
- 相互運用試験の完走、長時間試験（72 時間以上）、負荷試験

**出口条件**: `docs/interop-matrix.md` が埋まり、既知の制限事項が文書化されている。

## 進行上の注意

- **M0 で DST を作らないと、以降の品質が保証できない。** ここを省略しない。
- 機器（アナログゲートウェイ）の確定は M2 に影響する。**M1 の間に実機検証を進める**
  （docs/03 §6 の検証項目）。
- モデム伝送は機種依存の可能性が高い。**M3 で「成立しない」と判断した場合に備え、
  要件側に縮小案（拠点間 FAX のみ）を用意しておく**。
