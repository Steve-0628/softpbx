# 08. M0 受け入れテスト

M0 の出口条件をテストとして先に定義する。**実装はこのテストが通るように書く**。
テストは `engine-sim` 上の決定的シミュレーションで実行できること。

## 前提

- 仮想時計（時間を明示的に進める）と仮想ネットワーク（パケット損失なし）を使う
- 乱数シードは固定（`seed = 0x5EED`）
- 疑似 SIP 端末 2 台（`alice` / `bob`）を起動する

---

## AC-01: 内線登録

**Given** softpbx が起動している
**When** `alice`（1001）と `bob`（1002）が REGISTER を送る
**Then** 両方とも 200 OK が返り、登録状態が API から確認できる
**And** 認証失敗（不正パスワード）は 401/403 で拒否される

## AC-02: 内線通話の確立

**Given** `alice` と `bob` が登録済み
**When** `alice` が `1002` へ INVITE を送る
**Then** `bob` に着信し、応答で双方向の RTP が流れる
**And** 通話状態が API で `Answered` になる

## AC-03: 音声の伝送品質

**Given** AC-02 の通話が確立している
**When** 60 秒間、10ms 周期で G.711 パケットを送受信する
**Then** パケット欠損 0、並び順の乱れ 0（ロスなし経路）
**And** 1 パケットの処理時間が 1ms を超えない（中央値）

## AC-04: 通話の解放

**Given** AC-02 の通話が確立している
**When** `alice` が BYE を送る
**Then** `bob` に BYE が転送され、両側の RTP が停止する
**And** メディアリソースが解放される（リーク検出）
**And** 通話ログに 1 行（開始・終了・相手・結果）が追記される

## AC-05: 同時通話

**Given** 端末が 20 登録されている
**When** 10 通話を同時に確立する
**Then** すべての通話で RTP が正しく流れ、欠損 0
**And** 制御面（API）が応答可能である（通話中も停止しない）

## AC-06: 制御面の停止耐性

**Given** 通話が確立している
**When** 制御面の処理（API・設定適用）を意図的にブロックする
**Then** 確立済み通話の RTP は流れたまま維持される

## AC-07: 設定の適用とロールバック

**Given** 内線 1001 が登録されている
**When** 内線 1001 の表示名を変更する
**Then** 変更が Desired State に反映され、履歴が残る
**When** ロールバックを実行する
**Then** 元の値に戻り、再起動後も維持される

## AC-08: 通話ログ（NDJSON）の追記

**Given** 通話を 3 回行う
**Then** `log/call/` 配下に 3 行が追記され、既存行は変更されない
**And** プロセスを強制終了しても、追記済みの行は壊れない（部分行は再起動時に無視）

## AC-09: SIP 構文の頑健性

**Given** `sip-syntax` がビルドされている
**When** 壊れた SIP メッセージ（不正ヘッダ、巨大ボディ、分割断片）を投入する
**Then** パニックせず、適切に拒否される（エラーは 4xx 系で応答）

## AC-10: 決定的シミュレーションの再現性

**Given** シード `0x5EED` でシナリオを実行する
**When** 同じシードで再度実行する
**Then** イベント列とログがバイト単位で一致する
