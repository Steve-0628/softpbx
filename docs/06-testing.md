# 06. テスト戦略

自作の通信スタックは「動くように作る」より「**検証できるように作る**」ほうが難しい。
テスト基盤を実装より先に用意し、以降の開発は常にこの上に載せる。

## 1. レイヤ構成

```
[1] ユニットテスト      純粋関数（FSM 遷移、構文、番号正規化）
[2] プロパティテスト    任意のイベント列に対して壊れないこと
[3] 決定的シミュレーション  仮想ネットワーク・仮想時計で通話/FAX/モデム全体を再現
[4] ゴールデンパケット    実際の SIP/RTP や pcap と完全一致で照合（回帰防止）
[5] 相互運用テスト      実機・他製品との組合せ（手動 + 半自動）
[6] ファズィング        構文解析器への連続投入
```

## 2. 決定的シミュレーションテスト（DST）— 最重要

`engine-sim` クレートに、**仮想時計と仮想ネットワーク**を実装する。
乱数シードを固定すれば、失敗を必ず再現できる（FoundationDB / TigerBeetle の手法）。

### 2.1 用意する疑似相手

| 疑似装置 | 実装内容 |
| --- | --- |
| SIP 端末 | REGISTER / 発着信 / 保留 / 転送 / DTMF |
| アナログゲートウェイ | FXS のフックスイッチ・着信信号・FSK 番号通知を模擬 |
| **疑似 FAX 機** | T.30 状態機械（V.21/V.29/V.17、ECM 有無） |
| **疑似モデム** | V.8 の能力交換とキャリア確立、3.1kHz データ送受信 |
| 相手 PBX（MikoPBX 相当） | SIP トランク、番号帯ルーティング、Asterisk 系の癖 |
| 障害注入 | パケットロス、ジッタ、順序入れ替わり、遅延、再送、電源断 |

### 2.2 シナリオ例（M0 以降常に回す）

1. 内線 → 内線の 60 秒通話（G.711、欠損 0）
2. 着信 → 保留 → 復帰 → 転送 → 切断（通話ログが 1 通話として完結）
3. 拠点間 SIP トランク経由の通話（番号帯ルーティング）
4. アナログ FAX 機 → IP 間の T.38 送受信（V.17、ECM あり、ロス 0.1%）
5. G.711 パススルーでの FAX 送受信（VBD モード遷移を含む）
6. モデムの 3.1kHz 伝送（確立 → 送受信 → 切断）
7. FAX サーバ受信 → TIFF → PDF → メール送信
8. ネットワーク障害（ロス 10%）での FAX 失敗と再送
9. 設定変更の適用とロールバック

### 2.3 合格判定

- 通話: 音声パケットの欠損 0、遅延変動が規定内
- FAX: 全ページ送受信成功、イメージのバイト一致（または許容差）
- モデム: キャリア維持、データの誤りなし
- 通話ログ: 開始/終了時刻、相手、結果が 1 行で完結

## 3. プロパティテスト

FSM に対して次を機械的に確認する（`proptest`）。

- いかなるイベント列でも **ハング・パニックしない**
- いかなる状態でも **メディア路は一意に解放される**（リークしない）
- 終端イベントの後は必ず `Terminated` に到達する
- 設定の適用→ロールバックで元の状態に一致して戻る

## 4. ファズィング

| 対象 | ツール | 対象物 |
| --- | --- | --- |
| SIP メッセージ | cargo-fuzz | `sip-syntax` |
| SDP | cargo-fuzz | `sip-syntax` |
| T.38 UDPTL | cargo-fuzz | `t38` |
| TIFF / FAX イメージ | cargo-fuzz | `faxserver` |
| DTMF / RTP ヘッダ | cargo-fuzz | `rtp` |

CI では短時間のスモーク実行、定期実行でフル実行。見つかった入力はテストケースとして固定する。

## 5. 相互運用テスト（実機）

シミュレーションでは捉えられない差異を埋める。**機種確定後、表を作り切る**。

| 相手 | 確認項目 |
| --- | --- |
| MikoPBX（実機/VM） | SIP トランク接続、番号帯ルーティング、TLS/SRTP、転送 |
| Asterisk / FreeSWSSIP | トランク相互接続、T.38 交渉 |
| アナログゲートウェイ（NVR500/510 級） | §docs/03-6 の検証項目一式 |
| 主要 IP 電話機 | 発着信、保留、転送、DTMF、プロビジョニング |
| 実機 FAX（複数メーカー） | T.38 / パススルー、ECM、速度交渉 |
| アナログモデム | 3.1kHz 伝送の成立可否 |

## 6. CI

| ジョブ | 内容 |
| --- | --- |
| fmt / clippy | 常時（警告はエラー扱い） |
| test | ユニット + プロパティ |
| dst | 決定的シミュレーション（シード固定の回帰） |
| fuzz-smoke | 構文解析器への短時間投入 |
| build | x86_64 / aarch64 の両方 |

実機テストは CI 外。結果は `docs/interop-matrix.md` に追記していく。
