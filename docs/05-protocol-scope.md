## 2. 拠点間接続（MikoPBX 互換）

MikoPBX 同士は **SIP トランク**で接続する（SIP で呼制御、RTP で音声）。
本ソフトウェアは同じ方式で相互接続し、以下を実装する。

### 2.1 接続の基本形

```
[宅外拠点 MikoPBX] ── SIP(TLS) / RTP ── [softpbx] ── 内線
      番号帯: 3XX                      番号帯: 2XX
```

1. **番号帯の分離**：拠点ごとに内線番号帯を割り当てる（例: 自拠点 2XX、相手 3XX）
2. **トランク（プロバイダ）の相互定義**：相手 PBX を「プロバイダー」として登録
   - 認証はダイジェスト（ユーザー名は相手側のプロバイダー ID）または IP 認証
   - 発信元表示の扱いを相手仕様に合わせる（`fromuser` 相当の上書きをしない）
3. **発信ルート**：相手拠点の番号帯へ送る発信ルートを定義
4. **着信ルート**：プロバイダー経由の着信を内線へ渡す
   （MikoPBX 側ではダイヤルプラン `GoTo(internal,${FROM_DID},1)` 相当の振り分け）

### 2.2 ポート

| 用途 | ポート |
| --- | --- |
| SIP (UDP/TCP) | 5060 |
| SIP over TLS | 5061 |
| RTP | 10000–10800（既定。範囲は設定可能） |

### 2.3 相互接続で吸収する差異（クイーク層）

| 差異 | 対応 |
| --- | --- |
| Asterisk 系のセッションタイマ・re-INVITE 順序 | 相手側に合わせて再送/順序を調整 |
| `fromuser` の扱い（上書きしない設定が必要） | トランク設定に「発信元上書き」の有無を持たせる |
| 着信時の変数引き渡し（`set_var=IGNORE_TIME=1` 等） | 相手が時間条件で振り分ける場合に備え、時刻依存のルーティング差異を吸収 |
| SDP の記述順・不要属性 | 相手に合わせた生成（クイークデータ） |
| 早期メディア（183 + SDP）の扱い | 両対応（送る/無視する）を設定で切替 |
| 番号表記（+81 / 0 / 内線） | 番号正規化ルールをトランクごとに定義 |

### 2.4 経路

- LAN 内接続なら SIP (UDP/TCP) で十分
- インターネット経由は **SIP over TLS + SRTP** を基本とし、必要なら経路側で
  ルータの VPN（IPsec 等）を使う（本ソフトウェア自体はトンネリングを実装しない）
- NAT 越え：rport、対称 RTP、必要なら STUN。相手が NAT 内にいる場合の
  再登録・キープアライブ（OPTIONS）も実装する

## 3. 互換性クイーク層の設計

フィールド汚染（標準を守らない実装）への対応を、コードに散らさず**表データ**で管理する。

```toml
# quirks/<device-or-trunk>.toml
match = { vendor = "asterisk", role = "trunk" }
sdm_force_ptime = true
reinvite_order = "after_200"
accept_early_media = true
dtmf_method = "rfc4733"
```

- `sip-stack` / `media` は標準準拠のコードパスを書き、クイークは実行時に合成される
  設定（`EndpointProfile`）として注入する
- 新しい機種・相手に対応するときは**クイークファイルを追加**するだけにする
- クイークごとに対応するテストシナリオを `engine-sim` に追加する
